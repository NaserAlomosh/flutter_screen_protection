# Decision register

Proposed entries require maintainer review. Approve core choices at Phase 0. Security-sensitive defaults and optional policies also require review of their device evidence before release.

| ID | Context | Alternatives | Proposed selection and rationale | Risks | Status |
| --- | --- | --- | --- | --- | --- |
| ADR-001 | Channel commands and asynchronous observations | Methods only, events only, split channels | Preserve the existing MethodChannel and add EventChannel. Initial state and live updates share ordering. | Handshake and schema mismatch | Proposed |
| ADR-002 | State and ownership | Static singleton, per-widget observers, host controller | One owned controller per supported host with typed status and a shared broadcast stream. Explicit lifecycle avoids leaked observers. | Embedded engines and concurrent hosts need validation | Proposed |
| ADR-003 | Startup and signal loss | Reveal until capture, caller-only policy, mask on uncertainty | Opaque fallback for unknown and unavailable, explicit reveal override, always-mask option. | Visible behavior changes on older Android or transient detach | Proposed, security review required |
| ADR-004 | Selective protection | Replacement, blur, native surface, secure text-field hierarchy | Use mask or replacement for hiding content and blur for visual obfuscation. Keep arbitrary compositor exclusion out of scope and exclude undocumented hacks. | Initial capture frames and blur exposure | Proposed, security review required |
| ADR-005 | Whole-window policy | Automatic secure flag, host-only control, explicit lease | Evaluate optional leases that preserve pre-existing flags. Require coordination with other flag writers. | Host conflicts and Activity replacement | Pending optional scope and ownership |
| ADR-006 | Switcher privacy | Flutter-only cover, native hooks, defer | Evaluate Android Recents API and native iOS window overlays separately. Android Recents requires explicit host ownership. | Snapshot races and policy restoration | Pending physical evidence |
| ADR-007 | Platform floors and signals | Preserve scaffold floors, declare verified floors, raise detection floors | Plan Android 10 and iOS 15 as validation floors while separating install and feature floors. Prefer scene traits, with older screen fallback. Choose exact Flutter/Dart and native build floors after toolchain proof. | SDK drift and unsupported older hosts | Pending minimum/latest build proof |
| ADR-008 | Multiple iOS scenes and Android hosts | Global state, one supported bound host, independent host contexts | Validate one bound host per controller first and report ambiguous hosts as unknown. Add independent contexts only after explicit design and evidence. | Misattribution and scene changes | Proposed |
| ADR-009 | Android permissions and dependency scope | Declare in library, require host opt-in, heuristic detection | Use only the two normal permissions needed for supported detection. Decide manifest ownership after reviewing host opt-out and merged behavior. Reuse existing dependencies and evaluate lifecycle integration explicitly. | Downstream manifest surprises | Pending review |
